# AggiePulse app

From the package root, run `uv run python app/scripts/export_gtfs_static.py`, `npm ci --prefix app/frontend`, `npm run build --prefix app/frontend`, then `uv run uvicorn app.backend.main:app --port 8000`. Vite development mode proxies `/api` to port 8000.

`AGGIEPULSE_BACKEND=databricks` uses the SDK Statement Execution API with Apps environment OAuth credentials, or local profile `transit`, and warehouse `3c5b1dbf21774cde`. Every dataset is cached for 15 seconds. `/api/meta` reports backend, source and fallback reason. Dataset endpoints return explicit source fields. Missing tables and query/authentication failures use local landing data or packaged frozen snapshots; predictions use deterministic mock quantiles labelled SIMULATED. Snapshot GPS timestamps and ages remain visible. Empty SQL results remain empty rather than silently switching sources.

APIs: `/api/health`, `/api/meta`, `/api/routes`, `/api/stops`, `/api/vehicles/latest`, `/api/predictions`, `/api/events`, `/api/alerts`, `/api/history`, `/api/history/comparison`, `/api/replay?hours=24`, `/api/events/impacts`, `/api/plan?origin=STOP_ID&destination=STOP_ID&hour=12`.

Frontend tabs have URLs `#map`, `#forecast`, `#events`, `#plan` and `#history` (hash routing in `app/frontend/src/format.ts` `pageFromHash`/`hashForPage`; Back/Forward and deep links work). Forecast shows horizon strips, ranked route-directions, quantile bands and factor contributions. Events applies seed drop rules and local venue lookup, lists nearby routes and vendor alerts, and highlights the Tennessee game with a simulated prior. Events merge repeat showings with the same title and venue into one card ("Also: …"). Events cards show the nearest routes first with an approximate walk time (metres / 80 per minute). The trip planner searches direct route patterns and stop alternatives within 400 m; score is half scheduled headway + ride + walking + 20 × predicted load. Hourly headways are typical across feed trips, not a service-calendar-specific departure guarantee. History uses observed APC windows only, deduplicated by vehicle/GPS timestamp, with sample counts. History also compares archived forecasts with observed p90 load in completed target windows, for a chosen route and 15/30/60-minute horizon. It shows the p10–p90 band, MAE in load percentage points, interval coverage and matched-window n; fewer than five matches produces an insufficient-data state. Actuals are never simulated.

`planner.json` contains route-direction stop patterns, relative travel seconds and hourly headways. Static exports attribute TAMU Transportation Services. MapLibre loads in a separate chunk. The map colours route lines by the busiest direction’s predicted +30-minute median load, using the same <50% / 50–74% / 75%+ thresholds as measured bus rings; grey means no prediction. Routes have a keyboard-accessible forecast button as well as map click details. The map displays measured buses, active alert route highlights (not replacement detour geometry), and significance-scaled event venue markers. Overlapping buses are offset on the map: markers closer than ~44 px on screen are grouped and placed on a small ring around the group's centre (`spreadOffsets` in format.ts), recomputed when the zoom changes.

Deployment: build the frontend first, then `databricks bundle deploy -p transit`, start `databricks apps start aggiepulse -p transit`, and deploy with `databricks apps deploy aggiepulse -p transit --source-code-path /Workspace/Users/jasonli2026@gmail.com/.bundle/aggiepulse/transit/files/app`. `resources/app.yml` explicitly includes ignored frontend dist files. Apps installs `requirements.txt` and runs `backend.main:app`. The app resource grants CAN_USE on the warehouse. UC catalog/schema/SELECT grants must be applied to the generated service principal; they have been applied for this workspace.

Validation: `uv run pytest tests/app -q`, `uv run ruff check app/backend app/scripts tests/app`, `npm run build --prefix app/frontend`.

Replay uses `/api/replay?hours=1..168` (24 by default), anchored to the latest observed GPS timestamp in `silver.vehicle_pings`. SQL downsamples to the latest position per vehicle/minute and caps at 10,000 latest rows; the response reports its actual time range and whether the cap was reached. Play/pause, a time slider, and 1×/15×/60×/300× controls replay those positions. Positions expire after two minutes, so gaps remain visible. Route forecasts are hidden in replay to avoid presenting current forecasts as historical predictions. Replay has no TripSpark calls. Local landing files and the packaged observed `fallback/replay.json` keep it available when SQL or collection is down.

`DatabricksBackend.QUERIES` owns all SQL. Replay binds `hours` as an SDK `StatementParameterListItem(type="INT")`; comparison uses the constant `gold.pred_vs_actual` query, observed actuals only, with a completed-window filter and latest scoring run per route/direction/horizon/target. `route_directions` reads selected Silver mappings; nearby event routes come from GTFS stops within 600 m, ordered nearest-first. `/api/events` and `/api/events/impacts` rows include `route_distances` (route → metres to the nearest stop serving it, within 600 m). `/api/events/impacts` attaches `event_uplift` only where a prediction target overlaps the event (including two-hour approach/exit buffers). These values remain `SIMULATED PRIOR`, and are not isolated causal effects. The Tennessee card uses Nov 14 at Kyle Field, kickoff TBA; unavailable event-window uplift is explicit.

`/api/meta` retains per-dataset source/fallback metadata and adds `freshness`: original bus snapshot age/source, last real scoring timestamp and age, and latest observed Silver GPS/ingest timestamps. Pipeline lag is wall-clock age of the latest Silver GPS, not the metadata request time. Header status is amber for buses >3 min, scoring >30 min, or pipeline lag >40 min; red for buses >10 min, scoring >60 min, pipeline lag >120 min, frozen bus fallback, or missing metadata. Unknown pipeline data stays unknown in local mode. Packaged comparison actuals are observed snapshots; missing comparisons remain empty. Snapshot timestamps are never refreshed to pretend the data is live.
